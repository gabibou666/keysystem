06 / A FEW GOOD QUESTIONS

Before you hit publish.

A few things to know. For the details, head to our documentation.

Open documentation
How do I create a developer account?

Choose Create account and an available sign-in method: Google, Discord or email. Verify your address if you use email. Return with the same sign-in method to find your workspace.

Can other developers access my projects?

Dashboard management is restricted to the signed-in project owner. Project keys are scoped to a specific project. Published metadata is separate from your private project information.

What if I lose my key?

Contact the developer who issued it. Manually issued keys are shown in full once; the dashboard keeps a prefix for management. A checkpoint key may still be available in the original browser session. Otherwise, the issuer can revoke it and issue a replacement.

How do I contact support?

The available support channels are listed below. For a script-specific license issue, start with the script’s developer.

What happens when I publish an update?

A licensed release follows the current validated build and keeps its loader URL. Users receive the update on their next successful load. A free listing is a snapshot: publish it again to update that public version. Code already running does not update automatically.

Are checkpoints required?

No. Issue keys directly from your dashboard or backend API, or publish a free script. Checkpoints are an optional way for users to obtain a project key through your own provider account.

How is my source processed?

Your readable original is stored privately, encrypted at rest, and remains available for editing or download. Obfuscation is optional and off by default: Standard transforms locals and strings; Strong adds virtualization and has stricter compatibility limits. Builds run locally without executing your code. Protection cannot prevent reverse engineering or guarantee every executor; test your release. A privileged operator can access stored content.

Which obfuscation level should I choose?

Start with Standard and test the delivered build. Strong can increase size and startup cost; it rejects generic for loops, including pairs/ipairs. Unsupported syntax or resource limits fail without silently publishing the original. Both options are free, subject to service limits; your private original is kept. Standard / Strong
