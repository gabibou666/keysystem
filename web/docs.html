DEVELOPER GUIDE

Publish your script. Set up access.

Use this guide to publish a Lua script, give a user a license and test your project loader. Each project has its own source, licenses, checkpoint settings and private API token.

01. Create your project

  1. Create your account with Google, Discord or email, then open the dashboard. Email accounts must verify their address first. Use the same sign-in method to return to your workspace.
  2. Choose New project and name your script. Save the API token shown after creation if you plan to issue licenses from your own backend. You can manage licenses in the dashboard without using that token.
  3. Open Script hosting, paste your source or upload a Lua or Luau file up to 1 MB, then publish it.
  4. Open Licenses, choose a duration and issue a test key. Copy or download the full key before closing the result.
  5. Open Integration, copy your project loader and replace YOUR_LICENSE with the test key. Run it in an executor with HTTP and loadstring support before sharing it.

What to share with your users

Share the project loader and a project license. If you use checkpoints, share the public key page from the Checkpoints tab so users can obtain their own key. They do not need a developer account. Keep project API tokens and provider credentials in your workspace or backend.

02. Run the loader

The loader sends a project-specific license check before retrieving the published source. If device binding is enabled, the first successful check binds the license to that device. The executor needs HTTP requests and loadstring support.

getgenv().AUDIT_KEY = "ah_YOUR_LICENSE"
loadstring(game:HttpGet(
  "__SITE__/api/platform/v1/loader/PROJECT_UUID"
))()
Never distribute your API token. Keys start with ah_. Server API tokens start with ahp_ and belong only on your backend.

Publish the next version

Return to Script hosting and publish the updated source. Publishing replaces the current version; the project loader URL stays the same. Users receive the new version on their next successful load. Already running scripts are not updated automatically. Keep your own source backups if you need previous releases.

Source is delivered as uploaded after validation. If you use an obfuscator, process your script before uploading it.

03. Validate a license

Send a JSON POST request to /api/platform/v1/check. No API token is required: the license is the credential. A key from another project is rejected.

POST /api/platform/v1/check
Content-Type: application/json

{
  "projectId": "PROJECT_UUID",
  "key": "ah_YOUR_LICENSE",
  "hwid": "your-stable-device-identifier",
  "executor": "YourExecutor",
  "loadScript": true
}

On success, the response contains success: true, expiresAt, and, when loadScript is true, script and version. The first successful check binds a device when binding is enabled. Failed checks do not bind a device.

{
  "success": true,
  "expiresAt": "2026-10-10T12:00:00.000Z",
  "version": 1,
  "script": "-- your published Lua source"
}

04. Issue keys from your backend

Use the project's API token as a Bearer credential. A token can issue licenses only for its own project. Rotating it in the dashboard invalidates the previous token immediately.

POST /api/platform/v1/projects/PROJECT_UUID/licenses
Authorization: Bearer ahp_YOUR_PRIVATE_TOKEN
Content-Type: application/json

{
  "durationHours": 24,
  "count": 1,
  "note": "Order reference"
}

The response contains a licenses array with each full key, license id and expires_at. Store these keys securely before delivering them to your users.

05. Configure checkpoints

Choose one provider per project in the Checkpoints tab, save its settings, then share the public key page. The user starts on that page and returns in the same browser. Each session lasts 30 minutes and issues one key after verification. Set the default key duration in Project settings before users start their sessions.

LootLabs

  1. Enter your creator API token and choose 1–5 required tasks.
  2. Set the returned postback URL in LootLabs. Preserve its secret query parameter.
  3. Include unique_id for each task and click_id containing the generated link's puid. puid or sub_id is also accepted.

Unique authenticated task receipts advance the session. Saving again rotates the postback secret.

Work.ink

  1. Create a link in Work.ink, then paste its link URL and numeric link ID from the Work.ink dashboard.
  2. Share the public key page. A fresh destination override carries a one-time token back to this site.
  3. The platform verifies that token and its link ID with Work.ink before issuing a key.

Linkvertise

  1. Create a Target Link in Linkvertise. Set its destination to the Target URL shown when you save these settings. Paste your creator link URL and 64-character anti-bypassing token. Linkvertise applies this feature to all your Target Links, so configure their destinations before enabling it.
  2. Share the public key page. Linkvertise appends a short-lived hash to the destination after completion. The platform consumes it with Linkvertise's verification API.

LinkUnlocker

  1. Create a link in LinkUnlocker and paste its link URL and 64-character Redirect API token.
  2. Share the public key page. The platform creates an encrypted destination unique to each session.
  3. The decrypted return must contain the session proof, and the provider hash must validate, before a key is issued.
Provider accounts, ads and payouts are managed by each provider. Test a real flow in your own account before sharing it with users. If you change provider settings, test a new session and update any destination or postback URLs required by that provider.

06. Error reference

ReasonMeaning
invalid_keyUnknown license or key from a different project.
revokedThe project owner revoked this license.
expiredThe license expiry has passed.
hwid_requiredSupply a stable device identifier of 8–256 characters.
bound_to_other_deviceThe license is bound to another device. Ask the owner for a reset.
no_scriptThe project has no published script.

A user cannot get a key or load the script

  1. Check that the key and loader belong to the same project. A valid key from another project will not work.
  2. Confirm that the project has a published script and that the license is active. Check the latest validation events under Integration for the rejection reason.
  3. For a changed device, reset the license device binding from Licenses. The next successful check binds it again.
  4. For a checkpoint, start on the public key page and complete the provider flow in the same browser. If the session expired or verification failed, start a new checkpoint.
  5. Check the provider token, link ID, destination or postback settings against the provider-specific instructions above.

07. Limits and storage

  • 10 projects per developer account.
  • 10,000 licenses per project, including expired or revoked licenses.
  • 1–50 licenses per issuance request; duration from 1 to 8,760 hours.
  • One current published script per project, up to 1 MB.
  • Dashboard lists the latest 100 licenses and 30 validation events.
  • 120 platform requests per minute per client IP. Checkpoint sessions last 30 minutes.

Scripts and provider tokens are encrypted at rest. API tokens and license keys are stored as hashes. Completed checkpoint keys are temporarily encrypted so the originating browser can recover them during the session.
